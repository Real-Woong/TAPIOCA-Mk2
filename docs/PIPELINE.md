# TAPIOCA Ver2 — 파이프라인 한눈에 보기

> `docs/STRATEGY_SPEC.md`(전략 명세)를 **두 기기에 어떻게 나눠 올리는가**만 적는다.
> 전략 규칙은 거기 있고, 여기에는 «누가 무엇을 하고 어디에 저장하는가»만 있다.

## 한 줄 그림

```
 ┌─────────────── Mac mini (받아 오는 사람) ───────────────┐
 │  매일 장 마감 후                                           │
 │  ① 종목 목록 받기 → ② 종목별 일봉 받기 → ③ 한 묶음으로 포장 │
 └───────────────────────┬─────────────────────────────────┘
                         │  rsync (Mac이 밀어 올린다)
                         ▼
 ┌─────────────── Oracle (기록하고 판단하는 사람) ───────────┐
 │  ④ 포장 검수 (빠진 게 있으면 거부 + 텔레그램)              │
 │  ⑤ 원본 보관 (추가만 한다, 고치지 않는다)                  │
 │  ⑥ 계산 (RVOL·박스·ATR) → ⑦ 후보 상태 관리                │
 │  ⑧ 가상 매매(PAPER) 기록 → ⑨ 텔레그램 보고                │
 └──────────────────────────────────────────────────────────┘
```

**비유:** Mac mini는 «장 봐 오는 사람», Oracle은 «장부를 쓰는 사람»이다.
장 봐 오는 사람은 물건만 가져오고 판단하지 않는다. 장부 쓰는 사람은 시장에 안 나가고, 가져온 것만으로 계산한다.
그래서 계산이 이상하면 «받은 원본»을 다시 열어 같은 계산을 재현할 수 있다.

## 왜 둘로 나누나

| | Mac mini | Oracle |
|---|---|---|
| 강점 | 가정용 IP — Yahoo·Stooq가 열려 있을 **가능성**(미확인) | 24시간 켜짐, 공인 IP, 이미 systemd·텔레그램·백업이 있음 |
| 약점 | 잠자기·정전·공유기에 약함 | 키 없는 가격 소스가 막힘(기존 문서 기록) |
| 맡기는 일 | **받기만** | **보관·계산·상태·보고** |

## 단계별로 풀어 쓰기

| # | 이름 | 어디서 | 무엇을 | 결과물 |
|---|---|---|---|---|
| ① | 유니버스 | Mac | Nasdaq Trader 파일에서 ETF·테스트 종목을 뺀 목록 | `universe-YYYY-MM-DD.json` |
| ② | 일봉 수집 | Mac | 종목별 시가·고가·저가·종가·거래량. **최초 1회 80~120거래일**, 이후 매일 완료된 하루치 | `bars-YYYY-MM-DD.jsonl` |
| ③ | 포장 | Mac | 위 파일 + **매니페스트**(대상 N개·성공 M개·실패 K개·출처·받은 시각) | 한 폴더 |
| — | 전송 | Mac → Oracle | `rsync` (Oracle은 Mac으로 접속하지 않는다) | |
| ④ | 검수 | Oracle | 매니페스트가 없거나 실패가 많으면 **받지 않고** 「누락일」로 기록 | 텔레그램 경고 |
| ⑤ | 원본 보관 | Oracle | 받은 그대로 추가. 조정가는 소급해서 바뀌므로 **받은 날의 값**을 `fetched_at`과 함께 남긴다 | `data/raw/` |
| ⑥ | 계산 | Oracle | RVOL·Range20·CLV·ADDV20·ATR14. **원본에서만** 다시 만들 수 있다 | 계산 결과(버려도 재생성) |
| ⑦ | 후보 상태 | Oracle | 후보 → 확인 대기 → 확인 완료 → 돌파 / 만료 / 무효. 이벤트를 **줄로 추가** | `candidates.jsonl` |
| ⑧ | 가상 매매 | Oracle | 신호 다음 거래일 체결 가정, 비용·손절·청산 기록. **PAPER만** | `paper-trades.jsonl` |
| ⑨ | 보고 | Oracle | 텔레그램 한 장 — 새 후보·상태 변화·누락일 | 메시지 |

## ID 세 가지 (중복을 막는 열쇠)

| 이름 | 구성 | 어디에 쓰나 |
|---|---|---|
| 후보 ID | 종목 식별자 + 급증일 + 전략 버전 | 같은 급증을 두 번 세지 않기 |
| 이벤트 ID | 후보 ID + 이벤트 종류 + 발생 기준시점 | 같은 날 «확인·돌파·취소»가 여러 줄 생겨도 구분 |
| 일별 요약 키 | 기준일 + 종목 식별자 | 하루 한 줄 요약 |

«종목 식별자»는 티커만 쓰지 않는다. 티커가 바뀌어도 이어 붙일 자리를 처음부터 둔다.

## 기존 TAPIoca와의 관계

- **섞지 않는다.** `src/`(collect=Mac, server=Oracle) · `data/` · 별도 systemd 서비스·타이머.
- **LIVE 경로를 만들지 않는다.** 이 파이프라인에는 주문 코드가 없다.
- 기존 ETF 시스템의 판정(10/30 · 11/25)이 읽는 숫자는 건드리지 않는다.

## 통과 조건 (날짜로 정하지 않는다)

| 단계 | 넘어가는 조건 | 지금 |

| 2. 데이터 확보 | 전체 대상 OHLCV 확보 — 안 되면 **줄인 유니버스를 명시** | |

| 4. 상태 머신 | 재실행·누락일 복구·중복 이벤트가 안전 | |

| 6. 성과 평가 | **미리 적어 둔** 기간·표본 기준을 채웠을 때만 | |

## 알려진 한계 (숨기지 않는다)

- 무료 소스로는 **상장폐지 종목의 과거**를 못 받을 수 있다. 접근 시험이 `SIVB`·`BBBY`로 먼저 확인한다.
- 앞으로 쌓아도 티커 변경·기업행동·상장폐지 후 회수금액은 **자동으로 해결되지 않는다.**
- Mac mini가 꺼지면 그날이 빈다. Oracle이 누락을 감지해 알리고, 돌아오면 빠진 날을 채운다.
- 소액 계좌: 주문금액 = 허용 손실 ÷ 손절 폭(예: $0.25 ÷ 5% = $5). 실제 제약은 소수점 지원 종목 여부, 1회 한도 $6.7, 손절 폭이 넓어질 때 주문이 $1 아래로 줄어드는 경우다.
